Tina Performance / WorkerPool V2
实现说明（已更新为 SPSC 游标缓存 + 批量唤醒 + fetch_add 预留版）
============================================================

0. 目标与范围
------------------------------------------------------------
在现有 Remote IDE RPC Runtime 的基础上改造 WorkerPool。
不改 RPC 协议、Android 前端、Cache 策略及已有文件一致性语义。
使用固定 CPU 资源、任务分类、提交阶段主动分流、Per-producer
SPSC 环形队列矩阵、无 CAS 普通预留与批量按需唤醒，消除全局任务
队列、全局 head/tail、全局调度锁与冗余 futex 唤醒。
性能剖析交由外部 perf 工具采集，不在服务端热路径嵌入计时统计，
不再维护旧版共享队列 WorkerPool。

1. CPU 拓扑与配置
------------------------------------------------------------
目标机器：Intel Core i9-14900HX，8P + 16E，32 logical CPUs。
以下均指 Linux logical CPU ID，而非 lscpu 的 CORE 列编号。

EventLoop：4 个线程，绑定 CPU 0、2、4、8。
对应 SMT siblings：CPU 1、3、5、9，压测时由独立脚本下线或彻底隔离。
Worker：8 个线程，分别绑定 CPU 16~23。
其余 4P + 8E 留给 Fedora、Benchmark client 等。
Acceptor、Logger 共享 Tina 的 E-core 集合，不占独立核心。
连接分配沿用单 Acceptor 普通 Round Robin，不加权。

启动前验证 CPU online、affinity mask、SMT sibling/topology。
不要假定不同机器 CPU 编号相同。绑核失败明确报错。
Tina 本身不申请 root；SMT 离线与恢复交由 scripts/smt_ctl.sh，
记录原 online 状态，仅改动 1/3/5/9，结束时严格按原状态恢复。

config.cppm 默认配置：
    io_cpus = {0, 2, 4, 8}
    worker_cpus = {16,17,18,19,20,21,22,23}
    non_blk_worker_cnt = 3         // k
    blocking_workers() = 8 - k     // 派生值，不独立配置
    queue_cap = 128                // 每条 SPSC lane，2 的幂
    io_inline_threshold = 32 * 1024

支持 server 参数 --normal-workers <k>（1 <= k <= 7），默认 k=3；
穷举后依据实测决定是否改默认值。保留原有 server 参数与兼容性。

2. 任务分类
------------------------------------------------------------
Inline：ping、目录/小文件 Cache Hit（<= 32 KiB，沿用现有阈值
判定口径）。直接由原 EventLoop 执行，不进 WorkerPool。
Normal：>32 KiB 文件 Cache Hit 的响应数据准备/纯内存工作，不做
fork、磁盘 I/O 或其他可能长期阻塞的操作。
Blocking：Cache Miss 后文件系统读写、目录扫描、Git 子进程、
需要等待的终端/其他阻塞任务。按实际执行路径分类，不只看 method。

32 KiB 固定不调参；大文件仍走 Cache 并通过 shared_ptr 快照保活，
避免淘汰时 UAF。保持现有 revision、inotify、文件写锁及同连接
写后读顺序（in-flight write 登记，防止 inline read 越过未完成 write）。

Socket ownership：原 EventLoop 继续拥有 connection/fd、epoll
注册、发送队列、partial write 和 EPOLLOUT。Normal Worker 仅
offload 响应准备，完成后经 EventLoop::post_task 回所属 I/O 线程发送，
禁止多线程并发写同一 socket。

3. 队列结构：Per-producer SPSC 环形队列矩阵（带双端游标缓存）
------------------------------------------------------------
每个 Worker 逻辑上拥有自己的 inbox；按生产者 IO id 拆成 4 lanes。

                    IO0       IO1       IO2       IO3
    Worker 0        Q[0][0]   Q[0][1]   Q[0][2]   Q[0][3]
    Worker 1        Q[1][0]   Q[1][1]   Q[1][2]   Q[1][3]
    ...
    Worker 7        Q[7][0]   Q[7][1]   Q[7][2]   Q[7][3]

总计 32 条独立有界 SPSC 环形队列，每条 128 slots（2 的幂），总容量 4096。
每条 lane 严格只有 1 个生产者（对应 IO 线程）和 1 个消费者（所属 Worker），
彻底移除逐槽位 seq 原子变量与消费者 CAS 轮询循环，全队列 0 次 CAS / RMW。

核心布局（Cache Line 64B 对齐，消除伪共享）：
    struct alignas(64) Slot { optional<Task> item; }; // 消除相邻 tail/head 槽位伪共享
    // 缓存行 0（只读元数据）：capacity_, mask_, slots_
    // 缓存行 1（生产者独占写热点）：
    alignas(64) atomic<uint64_t> tail_{0};
    uint64_t cached_head_{0};          // 仅在 (tail - cached_head_) >= capacity_ 时刷新
    // 缓存行 2（消费者独占写热点）：
    alignas(64) atomic<uint64_t> head_{0};
    uint64_t cached_tail_{0};          // 仅在 head == cached_tail_ 时刷新

try_push(Task&& task)：
    t = tail_.load(relaxed)
    if (t - cached_head_) >= capacity_:
        cached_head_ = head_.load(acquire)
        if (t - cached_head_) >= capacity_: return false  // 失败不移动/消耗 task
    slots_[t & mask_].item.emplace(move(task))
    tail_.store(t + 1, release)
    return true

try_pop(Task& out)：
    h = head_.load(relaxed)
    if h == cached_tail_:
        cached_tail_ = tail_.load(acquire)
        if h == cached_tail_: return false
    out = move(*slots_[h & mask_].item)
    slots_[h & mask_].item.reset()     // 立即释放槽位内捕获对象
    head_.store(h + 1, release)
    return true

使用 uint64_t 无符号差值与 2 的幂位与，天然支持跨 UINT64_MAX 回绕。
Worker 按线程私有轮询游标扫描 4 条 lane，取到后移向下一条，防止高负载
单 lane 饿死其他 lane。无全局游标，无 Worker -> Worker 任务迁移。

4. Dispatcher：提交阶段主动借用与无 CAS 普通预留
------------------------------------------------------------
Dispatcher 不创建线程，是 4 个 IO 线程直接调用的无锁分诊台。
Normal Worker [0, k)，Blocking Worker [k, 8)。

每个 Worker 独立、64B Cache Line 隔离的原子 state：
    bit 63     = kIdleBit（已宣告空闲可借用）
    bit 0~62   = outstanding（reserved + queued + running 任务总数）

新语义：允许 kIdleBit 与 outstanding > 0 同时存在：
    state == kIdleBit               : 已宣告空闲，允许借用
    state == (kIdleBit | count>0)   : 已有任务预留，不可借用
    state == count (> 0)            : 正在工作，不可借用
    state == 0                      : 空载尚未挂牌，不可借用

关键操作：
  1. 普通 Normal / Blocking 预留：无需 CAS 自旋，直接单条 wait-free：
       slot.state.fetch_add(1, seq_cst);
     即使此时 bit 63 为 1，加 1 后变为 (kIdleBit | 1) != kIdleBit，
     立刻自动阻止其他 IO 借用该 Worker。
  2. 仅借用空闲 Blocking Worker 时使用精确 CAS：
       uint64_t expected = kIdleBit;
       slot.state.compare_exchange_strong(expected, 1, seq_cst, relaxed);
     保证多个 IO 并发借用同一 IDLE Blocking Worker 时至多 1 人成功。
  3. Worker 开始执行任务前，按需清除 kIdleBit（稳态连续执行时位已为 0，零写开销）：
       if (slot.state.load(relaxed) & kIdleBit)
           slot.state.fetch_and(kCountMask, seq_cst);
  4. 任务执行结束（含异常 RAII 守卫）或入队失败回滚时：
       slot.state.fetch_sub(1, acq_rel);

分配策略：
    Blocking：只在 Blocking Worker [k, 8) 中选 outstanding 最小者。
    Normal：先在 Normal Worker [0, k) 找最轻者；若 count==0 直接选用；
            若全忙则扫描 Blocking 区寻找 state == kIdleBit 尝试借用；
            借用失败或无空闲 Blocking 时，退回最轻 Normal Worker。
    同等负载用每个 IO 私有（64B 对齐）的 round-robin 游标打散竞争。

5. Worker 执行、批量合并唤醒、按需休眠与优雅退出
------------------------------------------------------------
每个 Worker 拥有独立 64B 缓存行的 atomic<uint64_t> wake_epoch：
    bit 0      = kSleepingBit（Worker 准备休眠前置 1，被唤醒或退出休眠时清 0）
    bit 1~63   = 单调递增唤醒纪元（步长 kEpochStep = 2）

批量合并唤醒（SubmitBatchGuard）：
  - 每个 IO 线程的私有 IoDispatchContext 维护 pending_wake_mask（uint64_t 位图）
    和 batch_depth；
  - 在一轮 conn->read() 或 inotify 批次外层挂 RAII SubmitBatchGuard：
    期间每次 SPSC try_push 成功只需 1 条本地位或指令标记目标 Worker，
    不碰 wake_epoch、不做栅栏、不调 notify_one()；
  - 离开作用域时（flush_submit_batch），若位图非空，整批仅执行 1 次
    atomic_thread_fence(seq_cst)，再用 countr_zero 遍历触达的 Worker，
    且仅当目标挂有 kSleepingBit 时才 CAS 清除睡眠位、纪元 +2 并调 notify_one()；
    已经在干活的 Worker 全程 0 次 futex 通知、0 次 wake_epoch 写争用。

Worker 主循环（热路径 0 睡眠检查、冷路径 Dekker 双栅栏防丢唤醒）：
    loop:
      if pop_from_lanes(task):
          if (state.load(relaxed) & kIdleBit) state.fetch_and(kCountMask, seq_cst)
          execute(task) + CountGuard::fetch_sub(1, acq_rel)
          continue
      if stopping && (state & kCountMask) == 0: return
      if !stopping && state == 0: CAS(0, kIdleBit)
      parked = wake_epoch.fetch_or(kSleepingBit, acq_rel) | kSleepingBit
      atomic_thread_fence(seq_cst)           // 与生产者 flush 栅栏配对，杜绝丢唤醒
      if pop_from_lanes(task): clear_sleeping_bit(); execute; continue
      if stopping && (state & kCountMask) == 0: clear_sleeping_bit(); return
      wake_epoch.wait(parked, acquire)
      clear_sleeping_bit()

五阶段优雅停机保持不变：停监听 -> 冻结 IO 读与新提交 -> shutdown 排空
WorkerPool（含已预留未发布任务）-> 等待发完响应（超时强关）-> join IO 线程。

7. Parameter sweep / benchmark（配合外部 perf）
------------------------------------------------------------
使用 scripts/sweep_normal_workers.sh 在固定 4P+8E 下交错穷举 k=1..7：

    ./tina server 3490 --normal-workers <k>
    taskset -c 6,10,12,14,24-31 ./tina_bench --workload ide_mixed --port 3490 --connections 4 --inflight 64

可选传入 --perf 使用 perf stat 采集服务端硬件与调度事件（task-clock、cycles、
instructions、context-switches、cpu-migrations、cache-misses），压测端自动输出
总体与分类（Inline / Normal / Blocking）P50/P95/P99 延迟并汇总为 CSV。
脚本通过端口占用检查、readiness check 与 trap 保障进程安全，绝不误杀无关进程。
